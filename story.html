The Architectural Story

How ubuntu-service evolved from a monolithic script into a clean 3-tier micro-library suite.

1. The Real-World Friction

On a production Ubuntu VPS, you maintain multiple micro-apps (like appointment-notifier, appointment-notifier-screens, quotation systems, and dashboards). Each app has its own systemd service running in the background.

Whenever you SSH in and run git pull to update code, the very next step is restarting the service. But engineers frequently forget the exact service unit name. Running systemctl list-units | grep ... every single time introduces friction and human error.

The Goal

Stand in any directory and simply type us restart. The tool detects the unit, verifies its port, and restarts only that specific service.

2. Why Decoupling Was Essential

As the tool grew, edge cases in real-world Linux environments emerged:

1

Multiple ExecStart Entries in Systemd

Some systemd units run cleanup scripts before launching Node, creating an array of commands. A monolithic parser calling execStart.replace() threw unhandled TypeErrors.

2

Side-Effect Separation

Testing detection and INI parsing shouldn't risk invoking systemctl restart. Detection is a pure read operation; restarting is an execution operation.

3

Reusable Micro-Packages

Other tools like vps-domain-inspect needed the detection logic without needing the CLI command runner.

3. The Three Packages Working Together

// Inside ubuntu-service orchestrator:
import { findServiceForDirectory } from "ubuntu-service-detect";
import { restartService } from "ubuntu-service-restart";

export function restartCurrentService(targetDir = process.cwd()) {
    const detected = findServiceForDirectory(targetDir);
    if (!detected.found) return { success: false, error: detected.message };

    const restartResult = restartService(detected.unitName);
    return { ...detected, restartResult };
}

With this structure, each package has a clear boundary, its own independent unit test suite, and clean folder-level discipline under src/v1/ and src/v2/.
