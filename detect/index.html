ubuntu-service-detect

Context-aware detection of systemd services matching the current or specified working directory.

📦 npm Package ↗ 🐙 GitHub Repository ↗ ← Back to Overview

🎯 Why ubuntu-service-detect Exists

When building automated VPS tooling, you frequently need to answer one question: "Which systemd service runs this directory?" `ubuntu-service-detect` provides a pure, read-only query engine with zero side effects. It never restarts services, never runs systemctl mutations, and safely parses complex units.

Safe Multi-ExecStart INI Parsing

Unlike standard INI parsers that crash when multiple `ExecStart=` entries exist, `ubuntu-service-detect` normalizes arrays and strings cleanly without throwing TypeErrors.

Multi-Strategy Scoring (100–40)

Matches by exact WorkingDirectory (100), subpaths (80), ExecStart binary targets (70), and package.json name heuristics (50).

Automatic Port Discovery

Scans systemd unit `Environment="PORT=..."`, CLI flags (`--port`), and local `.env` files to find the assigned port.

Fully Decoupled & Testable

Has zero runtime dependencies, runs in under 30ms, and features a 100% passing native Node.js test suite.

🚀 Quick Start

npm install ubuntu-service-detect
import { findServiceForDirectory } from "ubuntu-service-detect";

const result = findServiceForDirectory(process.cwd());

if (result.found) {
  console.log(`Unit: ${result.unitName}`);           // appointment.keshavsoft.com.service
  console.log(`Port: ${result.port}`);               // 3000
  console.log(`WorkDir: ${result.workingDirectory}`); // /root/KeshavSoft/appointment-notifier
}
